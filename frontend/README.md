## 🛰️ Overview & Scope

This module represents the complete **Frontend & Analyst Workspace** for the OrbitIntel / SatQuery-AI platform. As **Member 5**, the scope is strictly focused on creating a modern, responsive, and tactical geospatial user experience that consumes the REST API endpoints and data contracts exposed by **Member 4 (Backend Orchestration)**, while visualizing outputs from **Member 1 (Data Ingestion)**, **Member 2 (Semantic Retrieval)**, and **Member 3 (Bi-Temporal Change Detection)**.

The frontend operates in two flexible modes:
1. **Live Integration Mode (`VITE_USE_MOCK_API=false`)**: Communicates with Member 4's FastAPI backend at `http://127.0.0.1:8000` via Vite reverse-proxy.
2. **Offline Standalone Demo Mode (`VITE_USE_MOCK_API=true`)**: Self-contained demonstration mode equipped with realistic precomputed datasets (e.g. Tumakuru Industrial & Solar Corridor) for competition judging, offline reviews, or disconnected deployment. Also includes automatic graceful fallback if the live backend is temporarily unreachable.

---

## 🛠️ Technology Stack

- **Framework**: React 18 + Vite + TypeScript
- **Styling**: TailwindCSS + Custom tactical dark-mode design system (`#07090e`, glowing emerald/cyan/amber accents)
- **Geospatial Mapping**: Leaflet (`leaflet`, `@types/leaflet`) with OpenStreetMap and CartoDB Dark Matter basemaps
- **Icons**: Lucide React (`lucide-react`)
- **Routing**: React Router DOM v6 (`react-router-dom`)
- **State Management**: React Context (`IntelligenceContext`) for unified search, alerts, cluster state, and active map targets

## 🔌 API Contract Compliance (Member 5 ↔ Member 4)

All network traffic routes through `src/services/api.ts`, strictly adhering to Member 4's REST API specifications:

| Method | Endpoint | Purpose | Request / Response |
|---|---|---|---|
| `GET` | `/api/health` | Backend system health & vector index stats | Returns `SystemHealth` |
| `POST` | `/api/search/semantic` | Natural language text-to-image semantic search | `{ query: string, top_k: number }` → `SearchResult[]` |
| `POST` | `/api/search/image` | Image-to-image visual retrieval | `FormData(file, top_k)` → `SearchResult[]` |
| `GET` | `/api/alerts` | Retrieve automated anomaly & change alerts | Query: `?status=PENDING` → `Alert[]` |
| `GET` | `/api/alerts/{id}` | Retrieve individual alert details | URL param: `id` → `Alert` |
| `POST` | `/api/feedback` | Analyst verification feedback loop | `{ alert_id, action, rationale, analyst_notes }` → `boolean` |
| `GET` | `/api/clusters` | Spatial clusters generated by HDBSCAN | Returns `Cluster[]` |
| `GET` | `/api/change-detection/{id}` | Bi-temporal change detection report & mask | URL param: `id` → `ChangeAnalysis` |
| `GET` | `/api/metadata/{id}` | Detailed satellite metadata (STAC / sensor) | URL param: `id` → `TileMetadata` |
| `GET` | `/api/tiles/{id}` | Tile record & imagery source | URL param: `id` → `SearchResult` |

## 🚀 Running the Frontend

### Prerequisites
- Node.js (v18 or higher)
- npm or pnpm

### Installation
```bash
cd frontend
npm install
```

### Environment Configuration
Copy `.env.example` to `.env`:
```bash
# Live mode (connects to Member 4 FastAPI backend on port 8000):
VITE_USE_MOCK_API=false
VITE_API_BASE_URL=/api

# Standalone offline demo mode:
# VITE_USE_MOCK_API=true
```

### Development Server
```bash
npm run dev
```
The dev server will run at `http://localhost:5173/`.

### Production Build
```bash
npm run build
```
Creates an optimized, minified bundle in `frontend/dist/`.
